# xatodo 0.1.2

Multi-platform component packages.

## What changed

- The standalone and connect component packages are now built and published
  for all three superlive shell platforms. Release assets carry a platform
  suffix aligned with the shell's platform keys:

  | Asset (per form) | Platform |
  |---|---|
  | `xatodo-standalone-<version>-linux-x86_64.zip` / `xatodo-connect-<version>-linux-x86_64.zip` | Linux (x86_64) |
  | `xatodo-standalone-<version>-macos-aarch64.zip` / `xatodo-connect-<version>-macos-aarch64.zip` | macOS (Apple Silicon) |
  | `xatodo-standalone-<version>-windows-x86_64.zip` / `xatodo-connect-<version>-windows-x86_64.zip` | Windows (x86_64) |

- On Windows the server binary ships as `bin/xa-todo-<form>.exe` and the
  manifest launch command references it accordingly; the packaging scripts
  detect the host toolchain triple and fail on unmapped platforms instead of
  guessing. Nothing else changes: both forms keep the same manifest id, the
  connect form keeps its required config declaration, and package contents
  are verified by the same packaging-time proof chain on every platform.

## Upgrading from 0.1.1

Re-import the new package matching your platform
(`xatodo-<form>-0.1.2-<platform>.zip`) over the installed one (same
component id — the replacement keeps your edited `config.toml`).
