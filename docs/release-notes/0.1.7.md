## Fixes

### Connector proxy support: OS system proxy + TLS

The connector's HTTP client was built with reqwest default features disabled, which silently dropped two standard capabilities: reading OS-level proxy settings (macOS system proxy, Windows registry) and TLS. On hosts where the system proxy is the only working path to the daemon — typical GUI-session setups — the connector could never connect, and an HTTPS daemon endpoint could not be dialed at all.

reqwest is upgraded to 0.13 with defaults enabled (default-tls is rustls upstream, matching how x-agent consumes reqwest). The `use_system_proxy` config switch now follows ambient proxies in full — `http_proxy`/`https_proxy` env vars plus OS system proxy settings — when enabled; the default stays off (direct reach).

### Note for users behind a system proxy

If the connector cannot reach the daemon and the daemon is reachable through your OS proxy, enable "use system proxy" on the component config page.
