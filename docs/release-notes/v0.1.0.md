# xatodo 0.1.0

First public release. xatodo is a multi-user todo service: a Rust server
(axum + sea-orm, dual REST and MCP entries) with a React surface UI, and a
[superlive](https://github.com/drodreo/superlive) component.

## Artifacts

### Docker image (self-hosted backend)

```bash
docker run -d -p 8600:8600 -v xatodo-data:/app/data ghcr.io/drodreo/xatodo
```

Out of the box: sqlite at `/app/data/xatodo.db`, API on `0.0.0.0:8600`
(`/api/v1`, `/mcp`). Every API call requires a Bearer apikey — declare
users by mounting your own config over `/app/config.toml` (see
[server/config.example.toml](../../server/config.example.toml)).

Note: the bundled UI is the superlive component build (entry.js + surface
assets, no index.html — it targets the shell environment). A browser
hitting `/` gets a 404 until a standalone web form exists; the API is
fully functional regardless.

### superlive component packages

Two mutually exclusive forms of the same component (`xatodo`):

- **`xatodo-standalone-0.1.0.zip`** — the full backend embedded: the shell
  launches it locally with its own sqlite database. Import it in the
  superlive shell and use it right away.
- **`xatodo-connect-0.1.0.zip`** — a connector: the shell form that
  forwards REST/MCP to your self-hosted daemon. Its `config.toml` ships
  `[backend]` placeholders (endpoint + apikey) to point at the image above
  after import.

Installing one over the other replaces it while preserving your edited
`config.toml`.

## Requirements

- Component packages: superlive shell 0.1.0 or newer (0.4.x recommended)
- Docker image: any Docker host; no external database required (sqlite),
  postgres supported via `database_url`
